# 资料维护与经验审核

新增资料、整理案例、审核规则或归档反馈前完整阅读本文件；实际修改限于老师授权范围。路径与命令均以项目根目录为起点。总流程见[AGENTS.md](../../AGENTS.md)。

编号速查：`R01`公共转写规则，`E0001`转写例句，`D001`教材会话；`太阳-R01`和`太阳-M001`是太阳歌曲的本曲规则与修改案例。`待审02`是尚未通过的建议，与R02无关；其它歌曲使用不同简称，编号不随排序改变。

## 维护资料

原件各保留一份。加入资料后更新`资料/资料目录.xlsx`；读取正文和必要图示，将转写例句写入转写例句表。真实修改讨论每例写一个“编号 中文名称.md”文件，放在`资料/讲义制作过程存档/<歌题>/转写修改与辨析案例`。开头记录编号、手语歌、何时参考、核心辨析和关联规则，后面保留完整修改讨论。运行`python scripts/build_case_catalog.py`生成目录表；引导文字只在Markdown维护。没有修改记录的手语歌讲义表达不进入修改辨析；原句与转写不保留重复Markdown，辨析目录不复制正文全文。

讲义日期、授课老师、修订者据原文或老师确认填写，不从文件创建时间推断。资料目录以“手语歌（来源文件）”开头，版本或用途只记实质内容。表格第一行直接表头、灰白交替、无合并单元格。转写例句表和转写辨析案例目录都将“编号”放第一列，并冻结编号列与表头；资料目录只冻结表头。章节或会话名称并入“原文位置”，删除单独的“章节／主题”列。案例编号不随排序重编；新条目使用新编号。教材没有逐句作者讲解，不额外制造泛泛标签。

`资料/讲义制作过程存档`记录具体项目过程，不能把其中的图片高度、打法和格式当作通用标准。每次制作先读工作台内的“本次讲义格式要求”，保护老师现有转写、截图、裁图和批阅。

只处理老师提供的实质课后反馈，自评可选，与学生反馈分开。不添加反馈机制。统计填写人数而非出席人数，提取具体亮点、困难和建议；无实质建议如实说明，泛泛夸赞不作为改进证据。仅按要求合并已有Excel，有依据且有助备课的意见才补入案例。老师指定最终版作为该讲义的主要参照。

## 从修改案例积累经验

信息分区：本文件面向智能体，记录执行要求与工作流程；使用说明面向手语老师，只写老师需要提供什么、选择什么、如何提出任务和查阅结果，不写智能体内部执行要求。两者均不抄写具体转写规则或记号含义。具体内容只维护在公共转写规则、对应本曲转写规则和案例中；说明需要引用时提供链接，不复制规则正文。

老师修改了表达后，先记录原方案、采用方案和老师理由。再主动判断：这次修改只是本句选择，还是能帮助其它句子的办法。不要把每次修改都抽成规则。

有可复用经验时，先查已有规则和案例。对已有规则的补充提出具体增补文字；新方法用普通话写清“什么情况下可以用、可以怎么做”，找已有语料例子，明确哪些是老师原话、哪些是智能体分析。给老师看建议文字和例子，请其选择加入公共转写规则、只留本曲、修改后再看或不采用。

初稿完成后，请老师试打并邀请组长提出修改意见，由老师决定采用哪些意见，智能体完成修改；再整理转写辨析案例、提炼新转写规则，在定稿前集中交给老师审核，按审核结果整理规则与例句。老师练熟手语歌后确认是否定稿；需要修改时，调整转写、贴图与格式，再交老师练习复核。课后接收老师提供的反馈表和补充修改意见，整理实质性反馈并归档讲义。

待审核文件永久保留。新增条目读取文件开头的下一个编号，使用`## 待审NN 标题`，分配后递增计数；修改同一建议保留编号，已审结编号不复用。每条写状态、建议表述、适用情况与边界、依据、建议去向和待老师判断的问题；不把已经收录的案例汇总混进待审条目。

向老师汇报待审内容时默认每次集中给出3—5条，逐条列编号、建议文字、简短依据和建议去向，允许老师一次指定多条通过或分别修改。不逐条开启一轮对话；不足3条就一起给出现有条目，不为了凑数提炼规则。

审核由老师在对话中按编号决定，智能体先读取该条当前全文。通过采用该条已明确的建议文字与去向；改完再看继续待审；修改并通过按老师指定文字执行；只留本曲需明确歌曲；不采用则移除建议、保留原案例及老师理由；暂缓则继续保留。模糊答复只澄清缺失的决定，不自行扩大适用范围。文件中写“通过”不能替代人类在对话中的授权。详细流程见[数据库使用方法](../../资料/规则与例句数据库/数据库使用方法.md)。

通过后先写入公共转写规则或对应歌曲的本曲转写规则：增补沿用原规则编号，新规则分配未使用编号。在相关案例记录待审编号、老师的实际决定及最终去向，按批准范围关联例句与案例；运行`build_case_catalog.py`和`build_rule_index.py`更新目录和双向查询。确认目标内容及更新已保存后才移除待审条目，失败时保留条目并说明已完成和未完成的部分，重试不得重复插入。全部审结后只清空条目，保留文件及下一个编号。没有实际审核就不得自动通过。规则是备课参考，不能替老师决定字面翻译、提取内涵、自定义表达或补充背景的取舍。

新项目先选一个未占用的简称。详细编号说明放在使用这些编号的Markdown开头。

## 完成一次备课后的收编

一套流程结束后，将有用的对话和制作记录整理到`资料/讲义制作过程存档/<歌题>`。“本项目存档结构.md”只说明目录结构和文件作用。具体修改、采用方案和老师理由写入各个转写修改与辨析案例。对话记录保留老师原话、可见的AI答复和日期，作为追溯原话的存档；查词候选保留在本曲查词记录中。老师的理由与AI归纳分开记录，早期建议不能当作最终选择。

原件只保留一份，已有教材、手语歌讲义或定稿用链接引用。不要收录系统提示、隐藏推理、工具日志、账号信息或与讲义无关的私人材料。只能取得部分对话时，注明时间范围和缺失内容，不把整理摘要称为完整对话。反馈仅在老师提供后补入。

后续编写新歌讲义时，先按[转写与查词](转写与查词.md)完整阅读参照讲义与小班材料，再针对具体问题查询公共转写规则、转写例句和转写辨析案例。候选词条用于继续核对本曲的查词结果；对话记录仅在案例信息不足、需要确认老师原话或寻找尚未整理的案例时，按关键词查阅有关片段。不要默认通读整份历史对话，也不要把候选词条当作最终选词。

每首歌的“转写修改与辨析案例”文件夹保留“.content”，按编号列出案例标题和正文链接。新增或重命名案例时同步更新目录；目录不作为案例参与检索。

资料目录只收录完整讲义、讲义修改稿、反馈表、教材和特殊语言词典等成套资料。图片、视频、零散动作参考和原始对话记录留在项目存档内，不单列进资料目录。

规则与案例的双向检索：已有 `search_cases.py --rule R13` 从规则找案例。资料更新后运行 `build_rule_index.py`，从原表的关联标注及规则正文已有引用生成“规则与例句索引.json”。索引可以重新生成，不单独维护关联；“规则正文提及”不等于支持规则，需读正文判断支持、不同用法或边界。出现次数只反映资料收录情况，不能自动变成正确性权重。

手语歌讲义按歌名建子文件夹，原件放在 `资料/手语歌讲义/<歌名>/`，保留原文件名。移动原件后同步更新资料目录、转写例句的原件链接，并重建规则与例句索引和查询页面。
