# 构建与打包

供修改工具与准备发行文件的开发者阅读。所有命令从项目根目录运行；环境与常用命令见[TOOLING](../../scripts/TOOLING.md)。

## 工作空间与独立查询发行包

scripts/release/build_packages.py --full-only生成一个跨系统源码工作空间ZIP（默认标为development，不冒用已发布版本号）；可用--package-version设置经确认的版本。三系统共用源码，不捆绑NO-AI原生程序或运行库。系统区别集中在依赖配置、文件打开和预览实现中；字体与预览能力按实际环境核对，不能因为同包就宣称效果一致。

打包器只读取Git跟踪文件，按项目文件归属.json筛选；新代码未跟踪时会被排除，必要制作模块缺失会直接报错。通用工具、公共资料和工作台的空白使用说明可以入包，个人目录、本机下载词典、缓存、日志、构建工具及GitHub工作流不入包。每个ZIP含发行文件清单.json，记录所含文件的归属及SHA256；外部另附ZIP校验文件。清单为未来比较差异提供依据，尚不执行更新或自动合并用户修改。

工作台/、个人设置/、个人资料/、更新备份/按个人内容保护，只有工作台/使用说明.md作为起步说明可入包；个人设置/本地要求.md若存在，由接管智能体读取。资料/为仓库共享的资料，使用者自行改过的文件也须保留并比较；不批量移动已有资料，也不因归属标记授权上传。dictionaries/中的本机资源保留，明确跟踪的指拼、目录及下载配置作为公共资源入包。

NO-AI-ZONE继续按系统构建。Windows使用WebView2，macOS使用系统WebKit，Linux独立版随包提供Qt/PySide6；完整版仍按desktop-requirements等现有配置准备查询环境。工作流分别生成一个工作空间附件和三系统NO-AI构建附件，不自动发布。旧的硬编码v3.1.1上传工作流已移除，避免把开发源码附件上传到历史版本；v3.2.0发布统一工作空间包，旧v3.1.1附件和标签保持原状；NO-AI未变化，继续使用原版本。

## 制作工具维护边界

修改制作工具先定位现有函数，不追加第二套实现。make_handout.py保留唯一制作入口、Word排版及原件副本操作；handout_content.py负责内容读取核对，handout_images.py负责机械图片处理；handout_layout.py集中验证版式并登记检查覆盖，audit_docx.py及handout_format_audit.py独立核对成品。歌曲差异放在内容输入或版式配置，不写歌曲名分支；临时脚本不能实现Word排版。改动后运行当前JSON制作与原件副本的合成测试，对影响版式的改动逐页看样稿。当前源码不增加旧格式适配或覆盖更新接管模块；历史覆盖包的兼容代码不回灌本次开发源码，v3.2.0不提供覆盖更新包。

## 指令文件与构建检查

AGENTS保留总流程和阶段入口，docs/agent按任务保存执行要求，docs/tools保存详细工具规范。调整这些文件时先逐条核对原要求的去向，再检查首次备课、中途接管、只读检查与规则维护的阅读路径。不要依赖某个客户端自动加载子目录文件；AGENTS明确要求在进入阶段前读取对应文档。

运行`python -m unittest discover -s scripts/tests -v`检查制作、核对、文档入口及打包。文档测试只验证结构、链接与收录，不能证明智能体理解了所有要求，内容仍须人工通读。修改排版实现时另外逐页看合成样稿；只调整说明文件不需要反复调用Word。

GitHub工作流对PR执行三系统Python测试与工作空间打包核验；手动运行时另构建三系统NO-AI程序，不上传到Release。Actions使用Node 24运行环境，GitHub托管构建机负责提供，普通使用者无需安装Node。自托管构建机需满足对应Action的Runner版本要求。

YAML统一UTF-8、LF换行，由根目录.gitattributes约束；只规范有关文件，不顺带改写全部源码。提交前用git diff --check检查空白问题，换行整理与实际内容修改分开提交，方便审阅。
