# 构建与打包

供修改工具与准备发行文件的开发者阅读。所有命令从项目根目录运行；环境与常用命令见[TOOLING](../../scripts/TOOLING.md)。

## 公开工作空间与离线查询包

从审核过的公开源码运行以下命令，给每次构建指定一个新的输出目录。

```powershell
python scripts/release/build_public.py preview --out <输出目录>
python scripts/release/build_public.py workspace --out <输出目录>
python scripts/release/build_public.py no-ai --out <输出目录>
```

preview 用来检查缺少纯享版时的试用工作空间。workspace 只在获准公开的《26春手语小班知识纯享版》已经入库且完成审核后运行。脚本按 public-files.json 的明确路径选取文件，新增路径必须单独检查；工作空间 ZIP 内有发行文件清单，包外附 SHA-256。发布前核对清单、原件授权及 ZIP 内容。

公开 NO-AI-ZONE 只包含离线 HTML、公共规则及说明，Windows、macOS、Linux 共用。旧的三系统原生查询构建属于校内历史发行；公开发行使用上面的 build_public.py。

## 制作工具维护边界

修改制作工具先定位现有函数，不追加第二套实现。make_handout.py保留唯一制作入口、Word排版及原件副本操作；handout_content.py负责内容读取核对，handout_images.py负责机械图片处理；handout_layout.py集中验证版式并登记检查覆盖，audit_docx.py及handout_format_audit.py独立核对成品。歌曲差异放在内容输入或版式配置，不写歌曲名分支；临时脚本不能实现Word排版。改动后运行当前JSON制作与原件副本的合成测试，对影响版式的改动逐页看样稿。当前源码不增加旧格式适配或覆盖更新接管模块；历史覆盖包的兼容代码不回灌本次开发源码，v3.2.0不提供覆盖更新包。

## 指令文件与构建检查

AGENTS保留总流程和阶段入口，docs/agent按任务保存执行要求，docs/tools保存详细工具规范。调整这些文件时先逐条核对原要求的去向，再检查首次备课、中途接管、只读检查与规则维护的阅读路径。不要依赖某个客户端自动加载子目录文件；AGENTS明确要求在进入阶段前读取对应文档。

运行`python -m unittest discover -s scripts/tests -v`检查制作、核对、文档入口及打包。文档测试只验证结构、链接与收录，不能证明智能体理解了所有要求，内容仍须人工通读。修改排版实现时另外逐页看合成样稿；只调整说明文件不需要反复调用Word。

公开包发布前，在干净的公开源码快照上运行测试和上述构建检查。

YAML统一UTF-8、LF换行，由根目录.gitattributes约束；只规范有关文件，不顺带改写全部源码。提交前用git diff --check检查空白问题，换行整理与实际内容修改分开提交，方便审阅。
