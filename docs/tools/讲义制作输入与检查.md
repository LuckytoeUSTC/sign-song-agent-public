# 讲义制作输入与检查

调用make_handout.py或audit_docx.py前完整阅读本文件。命令与文件路径均以项目根目录为起点；技术准备见[TOOLING](../../scripts/TOOLING.md)，教学流程见[讲义制作与复核](../agent/讲义制作与复核.md)。

## 基本版式

制作前按选定参照填写本曲版式JSON，再传入 `make_handout.py --layout <版式.json>`。可配置：`font_name`（字体）、`font_size`（正文字号）、`title_size`（标题字号）、`heading_size`（小标题字号）、`image_height`（英寸）、`margin_horizontal`与`margin_vertical`（厘米）、`line_spacing`（正文行距倍数）。例如：`{"font_name":"SimSun","font_size":12,"image_height":0.79,"margin_horizontal":2}`。未填项使用默认值；`--height`可覆盖图高。制作JSON标题level支持1至3级，歌曲总标题显式设level:1；段落小标题默认level:2。段落样式、复杂表格等需要精确沿用时，直接局部编辑原Word，不为每首歌复制一套生成脚本。

## 当前制作输入（JSON version 2）

统一入口仍为make_handout.py；试排和正式稿使用相同输入与版式。此处version是数据格式号，不是发布版本号。新稿用version:2；旧制作数据和已有Word不自动迁移。旧JSON不再作为本入口的新稿输入，遇到会明确报错；老师要求更新旧稿时，核对原稿并重新整理当前输入，不直接改历史文件。

顶层为version、blocks及可选front_matter。新完整讲义用front_matter存放开头：song仅填歌名，teachers填写老师确认的署名（多位老师按本次确认的署名顺序填写），date填写实际授课日期YYYY.MM.DD；程序生成居中歌名及第二行右对齐的`--YYYY.MM.DD by授课老师署名`。日期和署名来自本次输入，缺项时先向老师确认。notation是可选的纯文字数组，每项一段记号说明，按输入顺序排在署名下。只列本稿实际使用的记号及已确认的含义；其中的*等字符按普通说明文字保留，不当作转写格式标记解析。程序不会自动套用旧记号含义或补写歌曲简介。老师改变记号时同步修改notation及正文。字体字号和段距分别用content_styles.byline、content_styles.notation配置；署名固定右对齐。

块分三种：标题heading（level:1为歌曲总标题，2为段落小标题，3为次级小标题，默认2）；text正文；lyrics与transcription歌曲句块。有front_matter时不再提供level:1标题，避免重复歌名；最小试排可以省略front_matter。每块可有唯一id。正文可用role选择content_styles。歌词和转写保留*斜体*、~~删除线~~、①②和++等原有标记；标记的实际含义从本次要求和参照核对，程序不判定某词是否该斜体。

sequence是图示行的有序数组，不另建图片数组。每项有type和at：at是transcription按“/”分隔后的词位，从1开始，通常按非递减顺序排列。同词位允许多个项目；一幅图同时表达相邻词位时可用连续数组，如at:[1,2]，不必为核对重复贴图。提供图示链时须交代全部词位，草稿可暂不提供sequence，核对时会提示“文字草稿”。

- image：path指向实际选用图片，相对制作JSON目录解析。可选crop、reference、content_scale以及内部entry/sense/source/action/alt/record；内部字段不印作中文标签。图片项不支持note。
- text：text为读者确实需要的短动作说明，按当前位置输出〔短说明〕，可以独立代表无图动作，不需要依附图片。填写普通文字，不添加格式标记或外层括号。
- omit：reason记录该词位不另展示图文的理由，仅内部核对，不打印文字或占位框。不要为凑齐词位逐字造图。

特殊图示组织可以在歌曲句块填写sequence_exception（非空文字），简要说明为什么不按普通词序排图、采用什么组织方式。此时允许at不按递增顺序，但词位范围、覆盖关系、选图/裁图和实际sequence顺序仍照常检查；例外说明不打印，检查结果列入人工核对。选择、同时或并列关系需要整体图解时，可把已经准备好的整体图解作为image输入，不必拆碎后硬排；这不是新增自由定位绘图功能。重复段继承原句的例外说明；omit_images:true时图示链及其例外说明一起省去。另有打法时独立建块。

样句和全曲文字初稿也使用teacher_note保存可核对的选词依据、候选比较和疑点；不要求提供sequence。生成讨论稿显式使用--edition teacher，说明独立成行并自动加【】，transcription只填实际转写。

块级teacher_note是可选的老师专属说明，程序在teacher版加【】；student版排除。内容按需要填写，不为每句编写翻译长解释。块级record可选且永不打印。块级note、images及未知字段会报错，避免把位置不明的说明静默印到图下或丢失。

```json
{"version":2,"blocks":[
 {"heading":"主歌一"},
 {"id":"a","lyrics":"示例句","transcription":"动作甲++/动作乙/动作丙","sequence":[
  {"type":"image","at":1,"path":"已有截图.png","entry":"内部词条名","source":"原件出处","action":"实际采用的动作部分","reference":true,"crop":[0,0,100,100]},
  {"type":"omit","at":2,"reason":"此处动作已在前图中表达，不单列图示"},
  {"type":"text","at":3,"text":"在此转向"}
 ],"teacher_note":"此处可比较两种表达，再做示范"},
 {"heading":"副歌"},
 {"repeat_of":"a","omit_images":true}
]}
```

crop为原图像素范围[left,top,right,bottom]，右/下边界不包含，须按实际图片填写。省略crop保留整张已选截图；Word原生裁剪不改磁盘原图，保持所取区域比例。合法坐标不保证动作完整，制作前仍要看原图。reference:true保留参考图虚线框。

repeat_of只引用前面定义的id，复用原句、转写、图示链及老师备注；可覆盖teacher_note或record，不能再提供一份正文/图示。omit_images:true省略整条图示链（含短说明），保留歌词转写及所选版本备注；不设则完整复用。重复引用不自动增加可见标题或说明。存在不同表达时单独建块，不强行同步。

```powershell
python scripts/make_handout.py '<内容.json>' --out '<学生稿.docx>' --layout '<版式.json>'
python scripts/make_handout.py '<内容.json>' --out '<老师稿.docx>' --layout '<版式.json>' --edition teacher
python scripts/audit_docx.py '<老师稿.docx>' --source '<内容.json>' --layout '<版式.json>' --edition teacher
python scripts/audit_docx.py '<学生稿.docx>' --source '<内容.json>' --layout '<版式.json>'
python scripts/audit_docx.py '<旧稿.docx>'
python -m unittest discover -s scripts/tests -v
```

edition默认student；制作和核对使用同一edition、layout及--height。docx副本模式保留原内容，不按edition筛选。audit_docx.py只读：错误为可确认的输入/成品不符（含图文交错顺序、斜体/删除线、图片字节/裁图/参考框、图高比例、标题层级及版本内容），警告提示潜在版式问题，人工核对项要求看原图、逐页预览和老师试打。核对顺序依据制作数据直接生成检查项，不调用Word生成器制作“标准答案”。不提供--source时只做通用检查，不因缺少制作字段阻断旧Word。脚本不验证文字的语义位置或动作自然度。

提供front_matter时还核对歌名、授课日期、署名和记号说明文字与输入一致，以及歌名居中、第二行署名右对齐。它不能从文字自动认定哪个名字是歌手、授课日期是否属实、记号解释是否正确；这些列入人工核对。

内容读取、字段核对和转写标记解析集中在handout_content.py；Word排版保留在make_handout.py，检查器独立读取成品结构。临时脚本不实现另一套Word排版。

当前开发源码不提供--update-action、本机接管状态记录和旧Markdown读取。本次未制作新的局部更新包；历史发布的覆盖包仅适用原发布说明指定版本，不适用于这次JSON格式变化。

参考图虚线框留边可在版式JSON中设置reference_frame_padding:true；只给包含参考图框的图片行增加至少“图高＋6磅”的行高并内收图框，普通图片行不变，不改原图像素或图高比例。默认false；可能影响分页，须逐页核对。

## 按内容配置格式与原件对照副本

以下版式字段按本次要求选用，未指定项使用默认值。image_space_before、image_space_after以磅设置图片段前段后，允许0；image_line_spacing为图片行距倍数。content_styles中正文段落角色可设置font_name、font_size、space_before、space_after、line_spacing；同段文字角色lyrics、transcription、note只设置字体字号；JSON正文块role指定角色，未指定用body，短注释用note。未提供的字段保留已有默认值。例如content_styles中的intro设置楷体，body设置宋体，note设置9磅；不要按歌曲名写代码分支。sequence中的text使用note角色的字体字号；同一行内不能为各项目分别设置段间距。老师备注使用teacher_note角色，未设时沿用note角色。

精细沿用已有Word，显式使用make_handout.py 原件.docx --input-format docx --out 新副本.docx --layout 调整.json。副本模式保留全部原图、尺寸、裁剪、间隔、页面宽度、样式和页眉页脚，只修改word/document.xml中明确指定的段落。paragraph_overrides以从1开始的正文段落序号为键，使用上述五个格式字段；段落序号与原件绑定，原件结构变化后先重新核对。不能给此模式传全局图高、边距或字体，也不推测段落角色；没有覆盖项即原样复制。

reference_frame_rows指定确实需要修正的参考图段落序号；reference_frame_padding_pt控制额外行高（磅，最小可用留边须逐页验证）。只处理指定行中已有虚线图框，保留图片宽高及横向间隔。新稿reference_frame_padding:true也只增加含参考图框行的行高，普通图行保持原有间距。未指定额外留边时沿用6磅，可明确减小。不要把某一份参照的段落序号或字体要求写入通用默认值。

## 扁图补白

补白是增加图片上下的白色画布：线图像素不变，整张图片按本曲统一外框高度插入Word后，里面的线图会变小、显示宽度也会收窄。它与reference_frame_padding不同：后者只给Word图框留行高，不处理图片画布。make_handout.py支持按已确认参数补白，不自动选择候选或决定程度，也不自动裁白边。image项目可选content_scale，例如0.7表示把所选区域的内容高度缩至统一外框高度的约70%；省略或设1保持原有处理。数值须为0至1之间的有限数（不含0）。

例如：`{"type":"image","at":1,"path":"原图.png","content_scale":0.7}`。同时指定crop时先取该矩形区域再补白，crop须为整数像素；未补白的图片仍沿用Word原生裁剪。调整后的PNG保存在新Word内部的媒体中，不覆盖磁盘原图，不再对派生PNG重复套用原crop。输入继续只维护原图路径、crop及content_scale，不要求另管一份派生图数据。处理函数位于handout_images.py，重复选图在单次制作内复用处理结果；依赖Pillow已列入requirements.txt。

补白在讲义贴图、排版完成后集中评估，老师确认前不生成补白图或改动讲义。

1. **筛选候选。** 优先定位拥挤或换行的图示行，从中挑选可瘦身图片；其次检查单只手、面部等大小及线条粗细明显失衡的图片，结合来源画风判断。空余充足且视觉协调的行通常不动。先查看完成贴图的实际页面，按已确认的可见范围统计有效图的宽W、高H和按本曲图高L显示的宽度L×W/H。结合可用行宽、图片间隔与同排正常图，标出横长或实际线图显得过大的候选。统计可用脚本完成；不采用统一宽高比阈值直接给全库补白。
2. **确定策略与目标。** 先检查过大的图间空格，以及能安全裁去的无用左右白边；矩形裁图可按原图像素坐标精确指定，不裁掉动作和箭头。仍需瘦身时，模型比较同排单只手、面部等实际大小及线条粗细，结合来源画风判断补白是否合适，选定内容显示高度h（h≤L），从最少补白开始。宽高比只是辅助，不能把多手形、多动作图的整张宽度直接当作视觉过大。
3. **集中确认。** 将候选按原句、所在页和同排图片定位，列出建议补白前后尺寸或内容缩小比例、判断理由及可能的换行变化，集中请老师选择。已确认的选择直接执行；未确认则停在建议阶段，不逐图询问。
4. **增加白画布。** 若有效图像尺寸为W×H，目标画布高度H新=ceil(H×L/h)。画布宽仍为W，上下分配H新−H像素白边，居中放入原图，多出的1像素放下边；RGB白色为(255,255,255)。只扩画布，不缩放或重绘原线图。content_scale=h/L；整数像素取整可能使实际比例略小于请求值。透明区域转白须确认其中无浅色有效线条。使用原图path、crop与content_scale时，程序负责先取区域再补白，不需要手动预裁。只有path已改为独立派生图时才清除旧crop和比例，避免重复处理。
5. **保存与使用。** 原图不覆盖。需要独立保存派生图时放本曲已有裁图/制作素材目录，名称能区分补白版本；默认派生图仅嵌入新Word；在图片record中简短记老师确认的调整依据，或复用已有处理记录。直接使用content_scale时，sequence的path继续指向原图，保留crop及比例，由制作入口生成嵌入的派生图；若老师已有独立补白图，则path指向该图，不再重复设置content_scale或原crop。不同时维护两份当前制作输入。
6. **复核。** 先比对补白前后，确认有效内容完整；再按本次layout试排，检查同排视觉大小、线条和箭头可读性、图片换行、分页及虚线框四边。可读性下降时减小补白；仍排不下可换行或按老师要求调整图高。数据检查只能确认选图、尺寸和裁图等事实，最终显示效果须看页面。

特殊情况下，可提示老师采用更精细的人工裁剪、不规则裁剪与交错放置；当前制作入口只支持矩形裁图和顺次嵌入，不能把这些高级排版说成已自动实现。若缩小会损害可读性，保留合理换行并交老师选择。对没有当前制作输入的既有Word，先保留原稿，只在授权副本中局部调整；现有docx副本模式不提供图片补白或替换，不为补白重建整份历史讲义。

## 制作配置与检查责任对应表

程序格式核对仅在提供--source时启用，使用与制作相同的--layout、--height和--edition；未提供配置文件时核对通用默认值。无制作输入的历史Word只做通用检查，不强加新稿默认规范。实际字体可用性、替代字体的显示效果及分页始终要看页面。

| 配置或内容 | 程序核对 | 页面复核／老师判断 |
|---|---|---|
| font_name、font_size、title_size、heading_size | 核对对应文字的中西文字体声明、字号；按Word半磅精度比较 | 字体是否安装、实际替代和字形可读性看页面 |
| margin_horizontal、margin_vertical | 核对各节四边页边距及当前固定A4纸张设置 | 打印机可打印区域、分页与翻页负担看页面 |
| line_spacing、image_space_before/after、image_line_spacing | 核对正文及图示段落的行距、段前段后，容许Word单位换算误差 | 实际裁字、跨行、拥挤和大空白看页面 |
| content_styles：body、自定义正文角色、byline、notation、teacher_note | 按对应位置核对字体字号、已生效的段距行距；署名右对齐另核对 | 风格是否适合本次讲义由老师选择 |
| content_styles：lyrics、transcription、note | 同一段内仅核对字体字号；这些角色不接受段距行距，避免配置被静默忽略 | 同段不能分别设置段距；改body或image_*控制整段 |
| image_height、crop、content_scale | 核对选图内容、裁图、补白结果、图高和比例 | 手形箭头是否完整、实际线图大小及是否值得补白由LLM看图后交老师确认 |
| reference、reference_frame_padding、reference_frame_padding_pt | 核对参考框存在性、可见黑色线条及启用后的最小行高 | 四边是否实际完整、线条和留白是否合适看页面 |
| heading/level、front_matter、sequence、重复省图、teacher_note/edition、斜体删除线 | 核对内容、层级、排列、标题署名对齐及格式标记 | 分段名称、记号实际含义、说明必要性、表达与动作自然度由LLM及老师判断 |
| paragraph_overrides、reference_frame_rows | 仅用于docx原件副本；回归测试验证指定修改及其它包内内容保留；新稿拒绝使用 | 不支持用JSON --source对照模式核查原件副本；与原件对照并逐页看 |

版式字段的覆盖登记集中在handout_layout.py的LAYOUT_COVERAGE，测试核对所有受支持的配置都有登记；登记本身不是检查正确性的证明，必须同时保留合法配置通过、误改能被发现的测试。新增配置时同步更新读取验证、检查实现、对应表和测试；不得只扩展生成器。未知格式、语义或无可比较依据的事项列为人工核对，不把推测当作确定错误。

检查器与生成器共用版式读取和标记解析，不共用Word渲染过程；图像机械处理复用公共函数，另用独立像素对比测试验证，防止同一处理错误在生成和检查时一起漏掉。
